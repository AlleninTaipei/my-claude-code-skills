# 純程式路線: 畫面技法

所有畫面都用 NumPy / OpenCV / PIL 算出來. 依主體的形狀選擇渲染方式.

## 目錄

1. 渲染方式選擇
2. 2D SDF 物件 (iphone17)
3. 平面貼圖加透視 3D (taichi)
4. 參數化剪影 (got)
5. 環境: 天空, 雲, 火, 雪, 粒子
5.5 介面, 監控畫面, 地圖 (jb)
6. 字卡與標題
7. 轉場
8. 效能

## 1. 渲染方式選擇

| 主體 | 方式 | 範例 |
|---|---|---|
| 輪廓簡單的產品 (手機, 手錶, 卡片) | 2D SDF 加假 3D 旋轉 | `examples/iphone17/render.py` |
| 大致是平面的產品 (主機板, 晶片, 電路, 地圖, 建築平面) | 程序化貼圖加透視相機, 凸起物件畫側面 | `examples/taichi/` |
| 人物, 動物, 怪物, 城堡 | 參數化骨架剪影加邊緣光 | `examples/got/figures.py` |
| 寫實人臉, 寫實場景 | 純程式做不到, 改走 AI 混合路線 | `references/ai-hybrid.md` |

純程式做不出寫實質感. 要靠打光, 光暈, 構圖和節奏撐起「電影感」, 不要硬拚寫實細節.

## 2. 2D SDF 物件

- 用 signed distance function 描述形狀: `rrect_sdf` (圓角矩形, 可做橢圓角), 圓, 膠囊. 遮罩 `clip(0.5 - sdf / aa, 0, 1)` 自帶反鋸齒.
- 只在物件的外框範圍 (bbox) 內計算, 不要整張畫面算.
- 假 3D 旋轉: 寬度乘上 `|cos θ|`, 側邊加一條寬 `d·|sin θ|` 的金屬邊框. `cos θ < 0` 時畫正面.
- 細節層次: 鏡頭的同心環, 鏡面高光點, 隨角度移動的反光帶, 輪廓邊光.
- 螢幕點亮: 以某點為圓心向外擴散的 reveal, 波前加一圈亮光.

## 3. 平面貼圖加透視 3D

做法見 `examples/taichi/render.py` 的 `Cam`, `warp_plane`, `draw_object`.

- 世界座標: x 向右, y 向下 (與貼圖相同), 高度 h 存成 `-z`. 這樣從上方看貼圖不會鏡像. 座標系統弄錯會讓文字顛倒或左右相反, 建立後先渲染一格確認文字方向.
- 相機: `Cam(target, dist, az, el, fov)` 以方位角, 仰角環繞目標. 特寫優先用長焦 (fov 26-30) 從遠處拍, 避免物件角點跑到相機後方.
- 平面: 投影四個角, 用 `cv2.getPerspectiveTransform` 加 `warpPerspective` 貼上, 只輸出到 bbox.
- 貼圖縮小時要選 mip 層級 (預先建 2x 縮小金字塔), 否則遠景會閃爍.
- 凸起物件 (散熱片, 插槽): 側面用多邊形填色, 頂面再貼一次貼圖. 依物件到相機的距離, 由遠到近畫 (painter's algorithm).
- 頂面貼圖用預乘 alpha 的 RGBA, 才能挖洞 (例如 CPU 插槽框).
- 自發光 (ARGB 燈條): 另存一張發光遮罩, 每格乘上隨時間變化的顏色, 值給到 1 以上讓 bloom 抓到.
- 高的物件側面加幾道水平溝槽, 否則看起來是一整片平板.
- 會動的向量元素 (資料脈衝, HUD 圓環): 投影 3D 點後在螢幕空間用 `cv2.line` 畫, 比畫進貼圖更銳利也更省.
- 金屬掃光: 合成頂面時另外累積一張 metal 遮罩, 最後在螢幕空間加一條移動的斜向亮帶乘上這張遮罩.

## 4. 參數化剪影

做法見 `examples/got/figures.py`.

- 人物 `human()`: 關節以角度描述 (0 向下, 90 向前, 180 向上), 參數有步態相位, 手臂角度, 劍的角度, 披風, 風力, 背面視角.
- 步態每兩拍一個循環 (`phase = t·π / BEAT`), 腳步自然對齊配樂.
- 比例要夠粗: 腿寬約身高的 0.09, 手臂約 0.06, 再加肩甲和衣擺. 太細會像火柴人.
- 打鬥: 每次劍擊拆成蓄力, 揮砍, 回位三段, 用 lerp 加緩動. 擊中瞬間加火花, 閃光, 鏡頭震動, 都對齊音樂的重音.
- 龍: 脊椎是沿曲線排列的圓, 翅膀是多邊形翼膜. 下拍幅度要限制, 否則翼膜會變成一大片斜板.
- 邊緣光: `rim(mask, dx, dy)` 往光源方向位移相減. 背光場景 (火, 月) 一定要加, 剪影才有立體感.
- 遠景人群用較小的尺寸, 顏色混入霧色; 近景加邊緣光. 兩排以上的不同捲動速度做出視差.

## 5. 環境

- 雜訊一律用 `videokit.fbm` (無縫版) 搭配 `scroll`. 普通 fbm 捲動時會出現直線接縫.
- 雲, 煙, 火在 1/2 或 1/4 解析度計算再放大, 省時且自帶柔焦.
- 火: 兩層不同速度往上捲的雜訊, 乘上由下往上變弱的形狀, 再對應到黑紅橘黃色階.
- HDR 火焰或光的值不要太高. 經過 ACES 後會被壓成白色, 讓火看起來像探照燈. 讓顏色偏紅橘, 亮度只靠 bloom 推.
- 粒子 (雪, 火星, 塵埃) 要畫在主體之前的背景層, 不然會像灑在物體表面的髒點.
- 光束: 多邊形, 大半徑模糊, 乘上捲動雜訊, 再加只在光束內可見的塵埃.

## 5.5 介面, 監控畫面, 地圖 (jb)

這類畫面完全由程式繪製, 適合穿插在 AI 生成鏡頭之間, 範例見 `examples/jb/assemble.py`.

- 監視器: 去飽和後染成綠灰色, 每 3 行壓暗一行做掃描線, 加強顆粒. 疊上時間戳, 攝影機編號, 閃爍的 REC 紅點.
- 行人追蹤: 在目標最清楚的那一格取樣板, 用 `cv2.matchTemplate` 在小視窗裡往前後兩個方向追蹤, 樣板每格以 15% 比例更新, 最後做 5 格平滑. 結果存成 `.npy` 快取, 多行程輸出時不用重算.
- 追蹤框: 四角括號比整框更像介面. 框的高度要涵蓋全身 (半寬的 2.3 倍), 比對數字逐步爬升, 確認時改成紅色.
- 地圖: 長幹道 + 數百條短巷 + 粗的河流曲線, 街區底色用最近鄰放大的雜訊做明暗. 路線用 polyline 逐段畫出, 加一層高斯模糊當光暈. 鎖定時用擴散圓環加十字線.
- 打字機字卡: 每個字元的出現時間由函式產生, 配樂的打字聲用同一份時間表.
- 訊號干擾轉場: 隨機水平切片錯位, RGB 通道反向位移, 再加幾個雜訊色塊, 強度用 sin 曲線在轉場中央達到最高.

## 6. 字卡與標題

- 字型: Windows 內建可用 Bahnschrift (科技感, 有 Bold/SemiLight 等 variation), Constantia (襯線, 史詩感), Segoe UI (乾淨). 系統沒有 Trajan, SF Pro 這類字型時不要假裝有.
- 字卡疊在複雜背景時, 先用 `videokit.scrim` 墊暗底. 如果還是有亮的圖案透出來, 就把字卡移到畫面比較暗的區域.
- 進場: 字距由寬收窄, 模糊轉清楚, 由下往上的遮罩露出, 加一條長出來的細線.
- 金屬標題: 縱向漸層加一條移動的亮帶, 外加一層大半徑的模糊光暈.
- 標題寬度 = 字寬 + 字距 × (字數 - 1). 字距動畫的起始值太大會超出畫面, 要算一下.
- 規格數字和平台名稱只寫有把握的; 不確定的在交付時說明, 請使用者確認.

## 7. 轉場

- 段落長度對齊音樂小節. 選 BPM 時讓每段剛好是整數小節 (例如 96 BPM 一小節 2.5 秒, 每段 5 秒是兩小節).
- 常用手法: 段尾短暫黑場加段首閃光 (配 braam), 甩鏡動態模糊 (`whip`), 交叉淡化, 光線開場 (一道光左右展開, 再上下分開露出下一鏡).
- 交叉淡化時不要再疊加白光, 中間幾格會變成灰霧.
- 整格全白的閃光不超過 1 到 2 格.

## 8. 效能

- 1080p 每格約 0.3 到 1 秒. 30 秒影片用 `videokit.encode(..., workers=12)` 平行渲染, 約 10 分鐘.
- 大型貼圖在每個 worker 第一次用到時才建立並快取 (lazy), 不要在主程式建好再傳.
- 全片渲染放到背景執行, 進度寫進 log, 期間可以先檢查音訊.
